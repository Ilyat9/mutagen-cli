## Находки

### P2: Отсутствует защита от неограниченного расхода на LLM запросы

**Что проверял:** Код использует Anthropic API и OpenRouter API для генерации мутантов и классификации.

**Что нашёл:** Нет жёсткого лимита на количество запросов или стоимость.

- `--max-mutants 25` ограничивает **количество мутантов**, но каждый может потребовать несколько запросов к LLM.
- Нет максимума по токенам или стоимости на пользователя / на запуск.
- `--classify-survivors` может вызвать O(n) запросов для каждого пережившего мутанта.

**Сценарий:** Пользователь с экспонентой в тестах или ошибкой в коде может случайно потратить $100+ за один запуск.

**Рекомендация:** Добавить опцию `--max-cost` или `--max-tokens-total` с разумным дефолтом; вывести смету **перед** запуском.

---

### P3: Отсутствует lockfile в репозитории

**Что проверял:** Воспроизводимость сборки и аудит зависимостей.

**Что нашёл:**
- `pyproject.toml` содержит `anthropic>=0.121`, `click>=8.1` и т.д. — range версий.
- Нет `poetry.lock`, `pip-lock` или аналога.

**Риск:**
- Новая версия `anthropic>=0.121` может вернуть ответ в другой форме, тесты падают.
- Зависимостью может управлять `hatchling` при установке, но воспроизводимость не гарантирована.

**Рекомендация:** Добавить `pip freeze > requirements.txt` или использовать `poetry.lock` для продакшена. Для разработки тоже полезно.

---

### P3: Инъекция в LLM-generated тексты частично покрыта

**Что проверял:** Безопасность обработки ответов LLM перед сохранением в отчёт.

**Что нашёл:**
- В `report.py` есть функция `sanitize_llm_text()` (строка 41), которая нейтрализует:
  - `![beacon](http://...)` инъекции
  - HTML теги (`<script>`, `<img>`, и т.д.)
  - Bare URLs (оборачиваются в backticks)
- Это применяется к описаниям мутантов перед сохранением в markdown/JSON.

**Хорошо:** Защита от prompt injection в выводе есть.

**Замечание:** Статус ✅, так как санитизация реализована правильно — XSS в markdown отчёте невозможен.
